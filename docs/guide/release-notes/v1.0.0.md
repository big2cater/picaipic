# Release Notes - PicAiPic v1.0.0

PicAiPic v1.0.0 establishes the first complete PicAiPic host/plugin baseline for Windows and Linux. It combines the existing local-first photo manager with a signed, permissioned AI plugin system and a cross-platform release pipeline.

## Highlights

- **Local-first photo management** — folder-based libraries, SQLite metadata, broad photo/RAW/video support, editing, deduplication, local AI search, and face features remain on-device.
- **Independent AI plugins** — plugins are discovered, installed, configured, started, stopped, probed, smoke-tested, invoked, cancelled, and uninstalled through the host.
- **Signed package trust** — Ed25519 package signatures, canonical cross-language verification, a user-managed publisher trust store, and release-build unsigned-package rejection.
- **Runtime profiles** — shared, plugin-private, and external Python environments with setup, package probing, runtime conflict detection, and manifest-driven model directory bindings.
- **Task safety** — bearer-token loopback authentication, bounded async task state, progress/cancellation, output adoption/discard, and default input-file staging.
- **Cross-platform releases** — Windows x64/ARM64 and Linux x86_64/ARM64 build pipelines, updater metadata, bundled models, and FFmpeg sidecars.

## Reliability and Compatibility Fixes

- Completed the active Lap → PicAiPic identity migration across the title bar, updater links, dependency dialogs, backup names, menus, PR artifacts, and current documentation.
- Fixed thumbnail and preview requests so the library id in the URL selects the correct SQLite database and cache, even when a request finishes after switching libraries.
- Added enforcement for plugin `minPicAiPicVersion`, optional `maxPicAiPicVersion`, and plugin API major compatibility.
- Standardized JavaScript dependency management on pnpm and aligned application/frontend/docs package metadata at `1.0.0`.
- Removed obsolete npm lockfiles and stale website repository links.

## Performance

- Converted Home panels and the main Content area to async components.
- Reduced the Home entry chunk from roughly 527 KB to roughly 15 KB; heavy panels now load only when needed.

## Security Scope

Implemented protections include package integrity/signatures, publisher trust, setup/runtime permission prompts, loopback bearer authentication, path containment for host-owned operations, output validation, and input staging.

Windows deny-ACL write confinement remains an explicit opt-in test mode because it changes real user-directory ACLs. Network blocking, Linux process sandboxing, strict write allow-listing, and signing-key revocation/rotation remain future work.

## Verification

The v1.0.0 baseline is checked with:

```powershell
pnpm --dir src-vite build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml -- --skip real_signed_zips_verify
.\scripts\check_plugin_host.ps1
.\scripts\package_plugin.ps1 -All -FailOnWarnings
```

Current automated results: frontend build passed, Rust formatting/check passed, seven non-ignored Rust tests passed, plugin-host regression passed, and both reference plugins passed strict packaging.
