# Release Notes - PicAiPic v1.2.0

PicAiPic v1.2.0 is the first fully public release of the local-first photo
manager. The repository is now open source (GPL-3.0-or-later, derived from
the [Lap](https://github.com/julyx10/lap) project), installers are published
for Windows x64/ARM64 and Linux amd64/arm64, the in-app updater works
end-to-end for all four platforms, and the docs site is live at
<https://big2cater.github.io/picaipic/>.

## ComfyUI Integration

- **Workflow import** — paste or pick a `.json` file: API-format exports
  import directly, UI-format graphs (the canvas format) are detected and
  offered for one-click conversion via `/object_info` widget ordering.
  Detection requires `widgets_values`, and a stray `nodes` key in an API
  export is rebuilt into clean keyed form instead of being corrupted or
  rejected.
- **Run, batch, cancel** — run a saved workflow against one or multiple
  selected photos, strictly serial with an interruptible cooldown between
  images so ComfyUI can release VRAM. Cancel interrupts ComfyUI and keeps
  images finished before the cancel. `POST /prompt` failures now carry the
  HTTP status and response text.
- **Results back in the album** — outputs download and import under
  readable names (`comfy_<workflow>_<n>.<ext>`), and the first imported
  result is scrolled into view and selected automatically.
- Settings: server address, connection test, unload models / free memory,
  cooldown, saved-workflow management (import is an upsert by name with an
  overwrite hint).

## Editor Save Fixes

- **Windows save bug fixed** — every image edit save (overwrite and
  save-as-new) failed at the temp-file flush step because the flush used a
  read-only handle; Windows `FlushFileBuffers` rejects those with access
  denied. Flushes now open read-write, and move-file staging had the same
  latent bug fixed.
- Regression pipeline tests cover save-as-new (new file, source untouched),
  overwrite, and PNG/WebP-source-to-JPEG saves.

## Result Discovery

- The "reveal first imported result" behavior now applies to every tool
  that lands a new image in the library: ComfyUI runs, batch save-as,
  photo frames, print layouts, and AI plugin results (grid and viewer), in
  addition to the editor's existing save-as-new reveal.

## Plugin Host

- **Optional and hideable** — third-party AI plugins remain supported
  (signed packages, publisher trust, bearer-token auth, input staging,
  output adoption), and the entire plugin UI can now be hidden with one
  Settings toggle; ComfyUI settings are a separate section and stay
  visible.

## Quality and Hardening

- ComfyUI download intermediates keep a sweepable `picaipic-` prefix and
  self-clean when the final rename fails.
- Destructive operations (trash, permanent delete, move/replace,
  batch/collage/frame exports) stage backups, journal staged deletes, and
  restore on failure — data-loss windows closed in prior audit rounds are
  part of this build.

## Packaging and Platform

- Windows x64/ARM64 MSI installers and Linux amd64/arm64 `.deb` and
  AppImage packages, all signed for the updater.
- The in-app update check works for all platforms: `latest.json` includes
  `linux-x86_64`, `linux-aarch64`, `windows-x86_64`, and
  `windows-aarch64` entries with signatures.
- Linux builds are marked experimental in the README until verified on
  real hardware.
